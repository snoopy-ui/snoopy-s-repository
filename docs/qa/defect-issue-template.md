# 缺陷 Issue 模板（E 登记缺陷时复制使用）

> 记录标准来源：分析文档 §13.3。每个实测发现都必须具备以下字段，缺证据的发现保留为「待验证」。
> 提交位置：在仓库新建 Issue，标题前缀 `[缺陷]`，关联对应测试项。

```markdown
标题：[缺陷] 一句话描述问题（含场景编号）

**版本与场景**
- 软件版本：
- 测试环境：
- 关联测试项：R__ / F__ / G__
- 样例编号：S__

**操作步骤**
1.
2.
3.

**实际表现**
（界面实际发生了什么，附截图/录屏链接）

**预期表现**
（按任务卡/验收标准应该发生什么）

**影响角色**
学生 / 老师 / 管理员

**优先级**
P0（阻塞基本交付/成果丢失/错归属） / P1（影响体验不阻塞） / P2（增强）

**是否可复现**
是（步骤如上，已复现 __ 次） / 偶发（记录触发条件） / 待验证

**建议**
（可选；修复方案由对应负责人决定，业务代码修复交回 B/C/D 原负责人）

**复验记录**
- 修复 PR：
- 复验结果与日期：
```

## 优先级判定参考

- **P0**：答案丢失不可恢复、提交错归属、收件状态无法解释、故障被展示成作业不合格
- **P1**：提示不清晰但可绕过、状态表达易混淆、恢复路径繁琐
- **P2**：体验增强、文案优化
