# 首轮试点计划（A v1.1）

负责人：A（`snoopy-ui`）。状态：准备阶段，等待正式课程量规、稳定源码基线和云端测试环境。需求 PDF 的试点规模是建议值，不是已批准承诺。

## 试点范围

先固定一门课程、两类脱敏任务（含无视频任务和至少一个必看视频任务），20–30 名学生和 1–2 名老师。正式试点前记录：

- 客户端/服务端版本、安装包 SHA-256、任务文件 SHA-256、`task_version`、`rubric_version`；
- 学校、课程、班级和测试身份的脱敏 ID；
- 任务发布窗口、视频完成策略、1200 秒计时策略、帮助/例外/重测政策；
- 测试环境地址、认证方式、备份点和回滚方法；不得把令牌、Cookie 或真实学生隐私放进仓库。

## 试点前置门槛

1. P0 缺陷 #7 已修复并由丁复验 R03；#8 已修复或有明确兼容性降级说明。
2. B/C/D/E 对 `docs/contracts/business-contract.md` 和 `samples/tasks/` 评审，分歧写入 A 决策日志。
3. 至少一条真实或等价业务闭环完成：领取 → 视频完成/无视频跳过 → 服务端计时 → 作答 → 自评/修改 → 冻结 → 收件 → 评价 → 教师反馈 → 修改重交。
4. 同名学生、跨校同学号、越权访问、断网重试、AI 故障和截止边界有可复现入口；未执行项不得标为通过。

没有真实云端、认证和备份恢复能力时，只能写“本地/模拟演示”，不能称为正式试点完成或教学效果验证。

## 观察指标与记录口径

| 指标 | 分母/记录方式 | 解释边界 |
|---|---|---|
| 任务导入成功率 | 合法任务尝试数；单独记录非法文件和解析失败原因 | 不把改名绕行当作兼容通过 |
| 首次进入作答耗时 | 从领取到 `ready_to_start` 的服务端/客户端时间 | 无视频任务必须单独统计 |
| 草稿恢复成功率 | 正常退出、重启、切题和断网场景分别统计 | 恢复草稿不等于提交快照 |
| 20 分钟规则 | `started_at`、`deadline_at`、19:59/20:00 写入结果 | 客户端显示不能替代服务端记录 |
| 技术故障分类 | 自查/上传/评价故障与作业问题分别计数 | 故障不得转写成合格或不合格 |
| 收件可靠性 | 同版重试、回执丢失、附件失败的唯一回执率 | 记录重复数和冲突数 |
| 教师复核 | 待复核数量、反馈耗时、覆盖理由完整率 | AI 结果不等于教师终评 |

A 在试点结束后按实际分母、异常样本、未完成原因和版本号汇总，不从小样本推导教学效果或 AI 准确率。

## 退出条件

- AC-01～AC-15、AC-19～AC-20 中纳入本轮的场景有真实或等价业务证据，`FAIL/BLOCKED/SKIP` 单列；
- 教师确认正式量规、帮助策略、重测和成绩发布规则；
- 发现的 P0 已关闭并复验，或 A 明确缩小发布范围并在发布说明中列出不可用能力；
- 升级、视频清理和备份恢复演练没有删除原件、笔记、历史版本或回执；
- E 提交回归报告，A 才能签署“候选版范围”，不能仅凭正常流程报告签署正式发布。
